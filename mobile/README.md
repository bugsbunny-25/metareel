# metareel mobile

The React Native (Expo SDK 58) app for metareel, for phones, foldables and
tablets on Android and iOS. The plan, decisions and roadmap are in
[`docs/mobile-app-plan.md`](../docs/mobile-app-plan.md).

It talks to a metareel server with a session token (`Authorization: Bearer
mrs_…`) from a "remember this device" sign-in, never an API key and never
cookies. An optional home-network address is used over plain HTTP only after
`POST /api/v1/auth/probe` proves it is the same server.

## Layout

| Path | What |
|---|---|
| `src/app/` | Routes (Expo Router): `sign-in`, `search` and the `log` sheet (full screen), and the tab shell `(tabs)/` (Tonight, Diary, Up next, Watchlist, Settings) |
| `src/app/(tabs)/_layout.tsx` | Android: one navigator for every window size, a bottom bar on compact windows and a rail on medium/expanded ones |
| `src/app/(tabs)/_layout.ios.tsx` | iOS: the system tab bar (`NativeTabs`), which iOS places itself (side strip on iPhone Duo, sidebar on iPad) |
| `src/layout/root-header.tsx` | Tab-root titles and actions: native large-title bar and toolbar buttons on iOS, a title row on Android |
| `src/app/(tabs)/(home,diary,up-next,watchlist,settings)/` | Each tab is its own stack; Title, Show, Watch and Subscriptions are shared routes inside every tab, so the bar or rail stays on screen and Back returns within the tab |
| `src/auth/` | Session store (Keychain/Keystore), sign-in, the home-URL probe, address validation |
| `src/net/endpoint.ts` | Picks the public or verified home URL per request; drops the home URL on a network error |
| `src/api/` | `schema.ts` (generated from `internal/openapi/spec/public.yaml`) and the typed client |
| `src/query/` | TanStack Query, its cache persisted to SQLite |
| `src/theme/` | `tokens.ts` (generated from `app/src/tokens.css`) and `useTheme()` (dark first) |
| `src/notifications/` | New-episode reminders: `plan.ts` (pure: upcoming episodes → reminders), `reminders.ts` (permission, settings switch, keeping the OS schedule in step), `use-reminders.ts` (sync on launch/foreground, open the show on tap) |
| `src/widgets/` | Home and lock screen widgets (`expo-widgets`): Up next and Break-even, SwiftUI on iOS and Compose on Android, fed from `GET /me/glance` by `sync.ts` |
| `src/nowshowing/` | "Now showing": iOS Live Activity / Android ongoing notification for the film you're watching, ending with a pre-filled log |
| `plugins/with-unique-extension-plists.js` | Gives the share and widget extensions their own `Info.plist` reference (both plugins would share one, which Xcode rejects) |
| `src/layout/window-class.ts` | Material window size classes (compact < 600 dp ≤ medium < 840 dp ≤ expanded) |
| `src/layout/ListDetail.tsx` | List and detail side by side on medium/expanded windows (Diary, Up next, Watchlist); on a half-open book foldable (Android, or iPhone Duo via UIKit's division region) the split sits on the fold |
| `src/screens/` | Title, Show and Watch views, used as screens and in the detail pane |
| `modules/fold-info/` | Local Expo module: the fold's bounds, orientation, posture (`useFold`, `isTabletop`, `isBookSplit`) from Jetpack WindowManager (Android) and UIKit reserved regions (iPhone Duo, iOS 27.1+); `expo-hinge` gives the angle and status on both platforms |
| `plugins/with-home-http.js` | Config plugin: HTTP only to the home hosts (`HOME_HTTP_HOSTS`), HTTPS everywhere else |

`ios/` and `android/` are generated by `npx expo prebuild` and not committed.

## Develop

Needs Node 24+, Xcode (iOS) and the Android SDK with Android Studio's bundled
JDK (Gradle 9.4 doesn't run on JDK 27 yet).

```bash
npm ci
npm run ios                     # dev build on a simulator, e.g. -- --device "iPhone Duo"
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" npm run android
```

Sign in to a local test server (development builds accept `http://`): run
metareel on a copy of the database (see `.claude/skills/local-verification`),
then use `http://localhost:<port>` on the iOS simulator or
`http://10.0.2.2:<port>` on the Android emulator.

Checks (all run in CI, `.github/workflows/mobile.yml`):

```bash
npm run typecheck && npm run lint && npm test
npm run check:generated         # API types and theme tokens match their sources
```

After changing `internal/openapi/spec/public.yaml` run `npm run gen:api`;
after changing `app/src/tokens.css` run `npm run gen:theme`.

## Builds and releases

Builds run on EAS (signing keys stay there, never in this public repo).
One-time setup, from `mobile/`:

1. `npx eas-cli@latest login`, then `npx eas-cli@latest init` and copy the
   project ID into the `EAS_PROJECT_ID` environment variable (locally and as
   the `EAS_PROJECT_ID` variable of the `mobile` GitHub environment). It is
   not a secret.
2. `npx eas-cli@latest env:create --name HOME_HTTP_HOSTS --value <your home host>`
   for the `preview` and `production` environments, so release builds may
   reach your home address over HTTP.
3. `npx eas-cli@latest credentials` to let EAS create the Android keystore
   and the iOS certificates; download a backup of the Android keystore.
4. Add an `EXPO_TOKEN` secret (an Expo access token) to the `mobile` GitHub
   environment.
5. Push notifications (watchlist arrivals), optional: let EAS create an APNs
   key (`eas credentials`, iOS → Push Notifications), create a Firebase
   project with an Android app `io.github.bugsbunny25.metareel`, upload its
   FCM v1 service account key to EAS (`eas credentials`, Android → FCM V1),
   and store its `google-services.json` as an EAS file variable named
   `GOOGLE_SERVICES_JSON` (the config reads the path from that variable).
   Then set `PUSH_ENABLED=true` on the server. Local episode reminders need
   none of this.

Then:

- `git tag mobile-v0.1.0 && git push origin mobile-v0.1.0` builds a signed
  APK on EAS and attaches it to that GitHub Release, and builds iOS for
  TestFlight (`.github/workflows/mobile-release.yml`).
- Merges to `main` publish the JS to the EAS Update `preview` channel.
- `eas build --local` builds on this Mac with the same profiles when the
  monthly EAS quota runs out.

The APK and the JS bundle are public: they contain no server address and no
secrets.
